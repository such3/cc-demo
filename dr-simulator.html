What you are seeing

Health checks & hysteresisThe manager probes both regions. It needs several failures in a row to fail over, and several passes to trust a region again, so one blip does not cause a flip. Try “Intermittent errors”.
RTO (recovery time)How long users are without service. Roughly: failed checks × interval + warm-up time. Faster checks lower it but raise false alarms.
RPO (data loss)Replication is asynchronous. Orders still waiting to be copied when the primary dies are lost for good. More lag means more loss.
Resync before failbackA restarted region has empty memory. It pulls a snapshot from the standby and only takes traffic after it is synced and healthy.

Simplified: real DNS failover also waits for resolver caches (TTL) to expire; here routing flips instantly once the manager decides. The “database” is in memory, so a crash genuinely loses unreplicated orders.
